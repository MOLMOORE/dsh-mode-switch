# 维护约定

## 文档分工

| 文件 | 写什么 | 不写什么 |
|---|---|---|
| `README.md` | 用户视角：它解决什么问题、怎么装、怎么配、怎么用 | 内部实现细节、历史包袱 |
| `CHANGELOG.md` | 每个版本的新增/变更/修复/决策，倒序 | 逐行代码改动 |
| `docs/ARCHITECTURE.md` | 两个正交维度、数据流、为什么这么设计 | 使用步骤 |
| `docs/LIMITATIONS.md` | 做不到的事与原因（含实测证据） | 计划中的功能 |
| 项目 `MEMORY.md` | 跨会话必须记住的结论：踩过的坑、被推翻的旧方案 | 过程流水、临时状态 |

## 版本与变更记录

1. 任何影响行为的改动都要进 `CHANGELOG.md`，写在「未发布」段落，发布时改成版本号 + 日期
2. 版本号走 `0.x.y`：新增档位/接口 → minor，修复 → patch
3. **被推翻的决策要留痕**：写清「原来怎么做 → 为什么不行 → 改成什么」，不要直接删掉旧结论
4. 每次踩到 harness 的坑（例如 `restrict` 只能收紧），同步写进 `docs/LIMITATIONS.md` 和项目 `MEMORY.md`

## 改代码后的验证清单

- [ ] `node --check index.js client.js catalog.js`
- [ ] 改 `client.js`：页面会热替换，直接看 chip
- [ ] 改 `index.js`：需要一次 profile 重组或重启 DSH
- [ ] 新建会话 → chip 显示「基础档 + 投影工具数」
- [ ] 发消息前点别的档 → 数字跟着变
- [ ] 发第一条消息 → 数字定格、胶囊置灰
- [ ] 老会话 → 显示「全量档」，不被改写

## 发布前

- [ ] 删掉临时诊断（`trace.log` 之类的写盘代码）
- [ ] `package.json` 的 `files` 覆盖所有运行时文件与文档
- [ ] `CHANGELOG.md` 的「未发布」改为正式版本
- [ ] 确认 `cordis.patch.yml` 只注册插件行，不声明 preset
